# DLNA Plugin for Lampa

Экспериментальный DLNA-плагин для Lampa на Android TV. Целевая платформа тестирования — Xiaomi Mi Box S 4K. Сервер-источник — MiniDLNA (ReadyMedia) на домашнем роутере.

## Текущий статус 0.6.5

**Последняя опубликованная тестовая версия — 0.6.5. Ручное испытание этой версии на Xiaomi ожидается.**

В линии 0.6.x реализованы каталог как Activity Lampa, Back из корня в настройки DLNA Bridge, переход в родительскую папку и возврат из ресурсов к списку файлов. Android recovery требует подтверждения и отдельного последующего выбора видео.

В 0.6.5 следующая Android-попытка автоматически разрешается после совпадающего external, полного цикла hidden → visible и возврата видимости, фокуса документа и управления исходной папке того же каталога. Допускаются external → hidden → visible и hidden → external → visible. Visible до external отклоняет цикл. Смена Activity, экземпляра каталога или папки, перекрывающий интерфейс, загрузка, ошибка и экран ресурсов инвалидируют незавершённый цикл. После закрытия перекрытия требуется новый полный цикл.

После принятого разрешения свежий OK или указатель позволяет выбрать файл и нужный ресурс. Остаточный keyup, удерживаемый OK и устаревший клик блокируются. Автоматическое разрешение само видео не запускает. При несработавшей эвристике доступно ручное recovery.

### Ограничения Android

Разрешение фиксируется как abandonment с причиной auto-return-unconfirmed. Завершение старого запроса остаётся неподтверждённым, физическая отмена не выполняется. Возможен поздний старый запуск, включая порядок p2 → p1. Принято срабатывание после Home → возврат в исходную папку при потенциально работающем старом плеере. External и create.abort() сами завершения не подтверждают.

Сохраняются ограничения create.abort() без external, раннего вложенного recovery-Modal и синхронного стороннего вмешательства внутри Settings/open. Штатный источник исследованных вмешательств в проверенной ревизии Lampa не найден.

## Цели проекта

- работа без установки дополнительного APK;
- отсутствие зависимости от постоянно включённого ПК, NAS или отдельного сервера;
- обнаружение DLNA/UPnP устройств в локальной сети;
- просмотр каталога DLNA MediaServer из Lampa;
- отправка воспроизведения из Lampa на DLNA MediaRenderer;
- управление воспроизведением там, где его поддерживает Renderer;
- выбор качества, аудиодорожек и субтитров только при наличии соответствующих возможностей источника и Renderer.

## Базовые возможности и меню линии 0.5.x

- раздел настроек Lampa с ручным вводом адреса MediaServer;
- SOAP `ContentDirectory Browse` по адресу `<сервер>/ctl/ContentDir` (путь MiniDLNA);
- разбор DIDL-Lite, навигация по папкам, постраничная загрузка (по 200, до 5000 элементов) и кэш с отдельной командой очистки;
- меню на штатном `Lampa.Select`; при несовместимом API — резервное DOM-меню;
- Back в папке — к родительской папке, Back в корне — возврат фокуса предыдущему экрану; после закрытия плеера фокус возвращается туда, откуда был запуск;
- запуск прямого URL через `Lampa.Player.play()`.

### Изменения по версиям

- **0.6.5** — автоматическое разрешение следующей Android-попытки по наблюдаемому возврату, защита свежего ввода и выбор ресурсов после разрешения.
- **0.6.4** — ограниченная диагностика событий ухода и возврата.
- **0.6.3** — возврат из корня каталога Activity в настройки DLNA Bridge, Android recovery с отдельным выбором видео.

- **0.5.5** — восстановление фокуса настроек после выбора и закрытия плеера; кэш сохраняется между открытиями.
- **0.5.6** — диагностика Android bridge (`AndroidJS` и др.) без вызова методов; проверка результатов регистрации настроек.
- **0.5.7** — расширенная read-only проверка `httpReq`, `get`, `getResp`, `dump`.

## Пока не реализовано

- SSDP/UDP multicast discovery;
- автоматический разбор UPnP device/service description и определение endpoint;
- управление AVTransport и отправка URL на Renderer;
- переключение аудиодорожек и субтитров.

## Почему без автоматического поиска

Обычный JavaScript в WebView не предоставляет UDP multicast API, а наличие объекта `AndroidJS` не означает, что приложение экспортирует сетевой API для SSDP. Документированный API для этого пока не найден (его наличие проверяет диагностика 0.5.6–0.5.7), поэтому сервер задаётся адресом вручную. Локальные HTTP-запросы также могут ограничиваться CORS, mixed content и настройками приложения.

Подробности: [docs/architecture.md](docs/architecture.md).

## Обратная связь для тестирования

- версия плагина, точная версия Lampa и способ её установки;
- версия Android/прошивки Mi Box;
- открываются ли каталог и папки, работает ли Back, запускается ли видео;
- текст уведомлений об ошибках;
- модель DLNA-сервера и, при возможности, ответ `Browse` на папку с видео;
- для будущего сценария Renderer — модель телевизора/приставки и URL его XML-описания.

## Совместимость и ограничения

Код ES5-совместимый: WebView Lampa на Android TV может поддерживать ограниченный набор API. Функция считается готовой только после проверки на реальном устройстве. Не вводите в плагин адреса устройств из недоверенных сетей.
