# DLNA Plugin for Lampa

Экспериментальный DLNA-плагин для Lampa на Android TV. Целевая платформа тестирования — Xiaomi Mi Box S 4K.

## Цели проекта

- работа без установки дополнительного APK;
- отсутствие зависимости от постоянно включённого ПК, NAS или отдельного сервера;
- обнаружение DLNA/UPnP устройств в локальной сети;
- просмотр каталога DLNA MediaServer из Lampa;
- отправка воспроизведения из Lampa на DLNA MediaRenderer;
- управление воспроизведением там, где его поддерживает Renderer;
- выбор качества, аудиодорожек и субтитров только при наличии соответствующих возможностей источника и Renderer.

## Текущий статус

**0.6.5 опубликована для ручного испытания на Xiaomi.** Подготовка и автоматические проверки завершены 7 ноября 2026 года. Результат ручного испытания 0.6.5 ещё не зафиксирован.

Реализовано:

- ручной ввод адреса MediaServer, SOAP ContentDirectory Browse через Lampa.Reguest.native(), DIDL-Lite, пагинация и кеш;
- каталог как Activity Lampa, навигация по папкам и выбор ресурсов видео;
- Back из корня в настройки DLNA Bridge, из папки в родительскую, из ресурсов в список файлов;
- блокировка повторного Android-запуска и ручное восстановление с подтверждением и отдельным выбором видео;
- ограниченный диагностический журнал жизненного цикла и событий ухода/возврата;
- автоматическое разрешение следующей Android-попытки после совпадающего external, цикла hidden → visible и возврата управления исходной папке того же каталога;
- защита от остаточного keyup, удерживаемого OK и устаревшего клика. Свежий OK или указатель позволяет выбрать файл и затем нужный ресурс.

Авторазрешение фиксируется как abandonment с причиной auto-return-unconfirmed. Предыдущий Android-запрос физически не отменяется. Поздний запуск, включая порядок p2 → p1, сохраняется. Возврат через Home также может разрешить новый выбор при ещё работающем старом плеере. При отсутствии подходящего цикла остаётся ручное восстановление.

SSDP, автоматический разбор device/service description, AVTransport, управление Renderer и переключение дорожек остаются целями проекта.

## Почему сначала диагностика

Обычный JavaScript в WebView не предоставляет стандартный UDP multicast API. Наличие объекта `AndroidJS` само по себе не означает, что Android-приложение экспортирует UDP-сокеты или сетевой API, необходимый для SSDP. Кроме того, локальные HTTP-запросы могут ограничиваться CORS, политикой mixed content и настройками Android-приложения.

Поэтому сначала необходимо проверить фактические возможности именно той сборки Lampa, которая установлена на Mi Box S 4K. Нельзя достоверно обещать автоматический поиск или управление DLNA, пока этот слой не подтверждён.

Подробности: [docs/architecture.md](docs/architecture.md).

## Предстоящий тест на Xiaomi

Указанное пользователем окружение — Xiaomi Mi Box S 4K, Lampa Android 1.13.5-581, веб-версия 3.4.5, плеер Android. Перед новым прогоном версии следует записать заново.

- Независимо проверить запуск → Back → исходная папка и запуск → Home → возврат. Зафиксировать журнал и запуск только после отдельного свежего выбора.
- Проверить остаточный keyup и удерживаемый OK, затем свежий OK.
- Проверить выбор нескольких ресурсов через OK и указатель, Back из ресурсов и повторный вход в каталог.
- Проверить ручное recovery, когда автоматическое разрешение не сработало.

Для каждого прогона записать исходную pending-попытку и границы журнала. Перезапуск приложения не подтверждает физическую отмену старого Android-запроса.

## Обратная связь для тестирования

Для следующего этапа полезны:
- точная версия Lampa и способ её установки;
- версия Android/прошивки Mi Box;
- результат диагностики из консоли/уведомления;
- модель DLNA-сервера или телевизора и URL его XML-описания;
- результат HTTP-проверки, включая статус ошибки.

## Совместимость и ограничения

Проект ориентирован на ES5-совместимый код, поскольку среда Lampa на Android TV может использовать WebView с ограниченным набором API. Реальное поведение должно проверяться на целевом устройстве. Не вводите в плагин URL или адреса устройств из недоверенных сетей.
