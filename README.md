# DLNA Plugin for Lampa

Экспериментальный DLNA-плагин для Lampa на Android TV. Целевая платформа тестирования — Xiaomi Mi Box S 4K.

## Цели проекта

- работа без установки дополнительного APK;
- отсутствие зависимости от постоянно включённого ПК, NAS или отдельного сервера;
- обнаружение DLNA/UPnP устройств в локальной сети;
- просмотр каталога DLNA MediaServer из Lampa;
- отправка воспроизведения из Lampa на DLNA MediaRenderer;
- управление воспроизведением там, где его поддерживает Renderer;
- выбор качества, аудиодорожек и субтитров только при наличии соответствующих возможностей источника и Renderer.

## Текущий статус

**Текущая версия в репозитории — 0.5.4.** Меню каталога использует штатный `Lampa.Select` и его Back/фокус; при отсутствии совместимого API включается резервное DOM-меню. Плагин вручную подключается к MediaServer, открывает каталог через SOAP Browse и запускает выбранный ресурс в Lampa, если его прямой URL поддерживается плеером.

Реализовано в `plugin.js`:
- регистрация раздела настроек Lampa и ручной ввод адреса MediaServer;
- SOAP `ContentDirectory Browse` через `Lampa.Reguest.native()`;
- разбор DIDL-Lite, навигация по папкам, постраничная загрузка и кэш;
- запуск найденного прямого URL через `Lampa.Player.play()`;
- диагностика `Lampa.Keypad`/`Lampa.Controller` и последнего события `back` в панели меню.

При штатном `Lampa.Select` Back внутри каталога возвращает в родительскую папку; Back на корне закрывает Select и возвращает фокус предыдущему экрану. Если API Select/Controller не соответствует ожидаемой сигнатуре, используется прежнее DOM-меню. Пока не реализовано:
- SSDP/UDP multicast discovery;
- автоматический разбор UPnP device/service description и определение endpoint;
- SOAP-запросы и управление AVTransport;
- отправка URL медиа на Renderer;
- переключение аудиодорожек и субтитров.

## Почему сначала диагностика

Обычный JavaScript в WebView не предоставляет стандартный UDP multicast API. Наличие объекта `AndroidJS` само по себе не означает, что Android-приложение экспортирует UDP-сокеты или сетевой API, необходимый для SSDP. Кроме того, локальные HTTP-запросы могут ограничиваться CORS, политикой mixed content и настройками Android-приложения.

Поэтому сначала необходимо проверить фактические возможности именно той сборки Lampa, которая установлена на Mi Box S 4K. Нельзя достоверно обещать автоматический поиск или управление DLNA, пока этот слой не подтверждён.

Подробности: [docs/architecture.md](docs/architecture.md).

## Установка для диагностического теста

1. Разместить файл `plugin.js` по доступному HTTPS-адресу.
2. В Lampa открыть **Настройки → Расширения → Добавить плагин**.
3. Вставить URL файла `plugin.js`.
4. Открыть настройки **DLNA Bridge — автономный режим**.
5. Проверить диагностику и, если есть известный URL описания устройства, выполнить HTTP-тест.

Сам GitHub-репозиторий с исходниками не является автоматически готовым URL установки плагина. Для установки нужен raw URL или другой HTTPS-хостинг, доступный устройству.

## Обратная связь для тестирования

Для следующего этапа полезны:
- точная версия Lampa и способ её установки;
- версия Android/прошивки Mi Box;
- результат диагностики из консоли/уведомления;
- модель DLNA-сервера или телевизора и URL его XML-описания;
- результат HTTP-проверки, включая статус ошибки.

## Совместимость и ограничения

Проект ориентирован на ES5-совместимый код, поскольку среда Lampa на Android TV может использовать WebView с ограниченным набором API. Реальное поведение должно проверяться на целевом устройстве. Не вводите в плагин URL или адреса устройств из недоверенных сетей.
