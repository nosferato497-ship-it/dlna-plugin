Прежнее сообщение о закрытии панели не считается воспроизведённым дефектом.

затем открывается слой settings и заново создаётся панель DLNA Bridge.
Целевой тест моделирует закрытие ввода перед сохранением и callback; проверяет
видимость панели, контроллер, новый адрес и подавление старого ответа A → B → A.
На test.2 пользователь подтвердил возврат в панель DLNA Bridge с кнопками серверов. Трасса session 1794546850051, события 37–61: Keyboard.destroy → settings_component → запись адреса → callback → краткий переход в главные настройки → панель DLNA Bridge. Конечное состояние: settings=true, input=false, фокус на адресе. Settings.close и перехода в head/расширения нет. Подтверждение кликом — PASS на test.2. Причина прежнего закрытия не установлена.

Прямые события onChange не записаны: наблюдатель загрузился до регистрации параметра; переходы внутри callback сопоставлены с кодом. Тест synthetic head-state recovery задаёт искусственный head и не моделирует реальный Input/Keyboard, всплытие событий и последующие обработчики. Его PASS не доказывает аппаратное исправление.
