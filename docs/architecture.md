# Архитектура и технические ограничения

## Требуемые роли

Проект должен поддерживать два независимых сценария:

1. **MediaRenderer:** Lampa передаёт URL потока на DLNA Renderer, затем управляет транспортом через UPnP AVTransport.
2. **MediaServer:** Lampa просматривает ContentDirectory сервера, получает ресурсы и запускает выбранный ресурс в плеере Lampa, если формат и сетевой доступ совместимы.

## Протоколы

- SSDP: UDP multicast на 239.255.255.250:1900 для поиска и объявлений UPnP.
- Device description: HTTP XML с описанием устройства и сервисов.
- ContentDirectory: SOAP Browse для навигации по каталогу.
- AVTransport: SOAP SetAVTransportURI, Play, Pause, Stop, Seek, GetPositionInfo и GetTransportInfo — при поддержке конкретным Renderer.

## Ограничения браузерного слоя

Стандартный WebView JavaScript не имеет универсального API для UDP multicast. WebSocket и Fetch не заменяют SSDP UDP. Поэтому возможны три пути:

1. Найти уже существующий документированный API в AndroidJS конкретной сборки Lampa.
2. Если такого API нет — реализовать ограниченный ручной режим с известными адресами и HTTP-доступом, если политика WebView позволяет.
3. Если автоматический SSDP обязателен, потребуется native bridge/APK или постоянно доступный локальный посредник. Это противоречит исходным ограничениям пользователя, поэтому такой путь не считать решением по умолчанию.

## CORS и локальная сеть

Даже если устройство отвечает по HTTP, WebView может блокировать чтение ответа из-за CORS, mixed content или сетевых ограничений приложения. Успешный ping/открытие IP в браузере не гарантирует доступность SOAP из JS.

## Форматы и дорожки

DLNA Renderer не гарантирует поддержку любого контейнера, кодека, профиля или URL. Переключение аудиодорожек и субтитров не является универсальной возможностью AVTransport. Эти функции зависят от Renderer, протокола передачи и самого медиапотока. В интерфейсе их следует показывать только при подтверждённой поддержке.

## Критерий готовности

Функция считается реализованной только после теста на реальном Android TV устройстве и фиксации модели/прошивки, версии Lampa, поддерживаемого сервиса и результата. Наличие UI-кнопки или успешного XML-запроса не является доказательством полноценной поддержки DLNA.
